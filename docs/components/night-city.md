# Night City and the notifications

Both live in `plugins/default/`.

Night City (`plugins/default/`): a theme (`themes/palette.json`) plus a mod (`hooks/`). It is the house look: the
notifications use Night City wording and the Onibi icon, and the installer's `paint` (`ui/view.ts`) maps named colours
to its palette where the terminal has 24-bit colour, leaving the rest to `styleText`. Claude Code hardcodes syntax
colours per base theme (Monokai for dark), so the installer always turns highlighting off. It also sets
`CLAUDE_CODE_TMUX_TRUECOLOR=1`: inside tmux Claude Code otherwise draws in 256 colours and the theme's indigos turn
grey.

The installer always sets `outputStyle: "concise"` unless the user chose a style, and `steps/output-style.ts` writes
`tools/installer/assets/concise-output-style.md` to `~/.claude/output-styles/concise.md` (after a clean slate's delete,
a differing file only replaced on a yes). It is part of the Claude Code setup only; the Codex step does not touch it.

The ccstatusline toggle writes `tools/installer/assets/ccstatusline-night-city.json` (`ccstatusline.json`, the old stock
config, is kept only so the installer recognises and replaces it): Powerline (needs a Nerd Font), and since Powerline
mode draws a gradient in its first colour only, the ナイトシティ sign is one widget per glyph.

Nothing draws above the prompt now: ponytail's band is vendored but never loads, and the flows band and Onibi's visits
were removed in commit c2032c1, "Vendor ponytail v5 and make its band the only one above the prompt (#66)". A revert no
longer applies, because the manifests and the ponytail pack have moved since; to bring them back, take
`plugins/flows/hooks/flow.ts`, `plugins/flows/hooks/register.tsx` and `plugins/default/hooks/onibi.ts` from that
commit's parent and declare them as an `extensions` entry.

Night City's mascot PNGs (`assets/`) are generated by `scripts/draw-mascot.mjs`; never edit them by hand.

## Notifications

Notifications (`plugins/default/`, formerly the notify plugin): the neutral `hooks/hooks.json` entries (`turn.finished`,
`permission.requested`, `question.asked`, `notification.received`, all `background`) run the shared
`hooks/runtime/run.mjs` the compiler packages, which calls `main` in `hooks/lib.mjs` (Node standard library only; tests
in `hooks/lib.test.mjs`). On Claude Code they compile to Stop, Notification (`permission_prompt`, `elicitation_dialog`)
and PreToolUse on AskUserQuestion; on Codex to Stop, PermissionRequest and PreToolUse on `request_user_input`
(`notification.received` has no Codex event). Linux talks D-Bus via `busctl`, falling back to `notify-send`; Windows
runs an inline PowerShell WinRT toast. Focus comes from tmux when `$TMUX_PANE` is set (not on Windows), and on Windows
from the foreground process. The installer always sets `preferredNotifChannel: "notifications_disabled"`.
