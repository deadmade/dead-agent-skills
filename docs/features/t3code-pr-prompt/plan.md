**Goal:** the Close step every conductor shares writes the PR title and body by T3 Code's rules
([spec.md](spec.md)).

**Architecture:** one prose change in the shared step `plugins/flows/steps/close.toml`; the build composes it into the
six conductors. `pstack-picks:blast-radius` leaves the step's `uses`, and `scripts/flows-uses.mjs` regenerates the
flows README's uses tree from that.

## Global Constraints

- PR text format: resolved in `plugins/flows/steps/close.toml`; never seen by the conductors' SKILL.md files, the
  host templates or the packs.
- One implementation gets no interface; one caller gets no helper; no option nobody sets.
- No Claude-only names in the step (`harness-compiler lint`); host wording stays in the `{{user-runs}}` and
  `{{watch-checks}}` tokens.
- Keep both `overrides` markers and the sentences they quote.
- Stack: none from `stack-packs.md` (Markdown and TOML only).

## Test seams

- `npm test` (check-repo: build, compiler lint, check 7 "the text names each use", the overrides markers, the README
  uses tree): catches a broken composition, a dangling or unnamed use, a stale README tree. Misses whether the
  wording produces a good PR body.
- No new tests: the change is prose, which gets none.

## Before you write

Reaches: `close.toml` (text and `uses`); the six composed conductors (generated by the build); the uses tree in
`plugins/flows/README.md` (generated by `node scripts/flows-uses.mjs`; only /implement's line changes). Nothing else quotes the old body wording
(verified: grep for `Door` and `smallest picture` outside the packs finds only `close.toml`). User-facing risk: none
to data; a conductor's PR body changes shape for every user on the next release.

### Task 1: Replace the PR body rules in the Close step

**Does:** swaps the Close step's PR body instructions for T3 Code's title, Summary/Testing and template rules.
**Depends on:** none
**Adds:** nothing new
**Size:** ~20

**Files:**

- Modify: `plugins/flows/steps/close.toml`
- Modify: `plugins/flows/README.md`

Steps:

1. In `close.toml`'s **Push and PR** list, replace the first bullet ("The body, saved to a scratchpad file: why; what
   changed, …; verification, with the before/after output where behaviour changed.") with:

   ```markdown
   - The title is concise and specific.
   - The body, saved to a scratchpad file, is markdown. When the repository has a pull request template
     (`pull_request_template.md` in its root, `docs/` or `.github/`, any case), the body follows the template's
     markdown structure, fills its sections for this change and drops its HTML comments; with several templates in a
     `PULL_REQUEST_TEMPLATE/` folder there, pick the one that fits and name it at the gate. Otherwise it has the
     headings `## Summary`, with short bullet points, and `## Testing`, with bullet points naming the concrete
     checks the run made (the commands of its last check run and their result), or `Not run` where a check was not run.
   - Never put absolute local paths, image embeds or attachment links in the body: reviewers can't open them.
   ```

2. Remove `"pstack-picks:blast-radius",` from the step's `uses` list.
3. Run `node scripts/flows-uses.mjs`: it rewrites the README uses tree and runs the build. It also rewrites
   `plugins/catalog.json` and `plugins/flows/plugin.json` with no dependency change (pstack-picks is a pack), so restore
   both: `git checkout -- plugins/catalog.json plugins/flows/plugin.json`. The README diff is exactly one line:
   `blast-radius, ` leaves /implement's `pstack-picks` line (it had it only through the Close step).
4. Read the composed Close section in `.claude-plugin/flows/skills/implement/SKILL.md` and the Codex copy under
   `.agents/plugins/flows/`: the new bullets are there, the picture / blast radius / Door wording is gone.
5. If the regeneration changed `plugins/flows/README.md`, format it:
   `npx -y prettier@3 --write --no-config --print-width 120 --single-quote plugins/flows/README.md` (TOML stays
   unformatted without nix).
6. Run `npm test`; compare any failure with the five known `EPERM ... symlink` failures before chasing it.
