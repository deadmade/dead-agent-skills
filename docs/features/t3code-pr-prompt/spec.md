# T3 Code PR text in the Close step: spec

No pictures: a one-file change with no new boundary.

## Goal

When a conductor's Close step opens a pull request, it writes the title and body the way T3 Code's
`buildPrContentPrompt` does ([prior-art.md](prior-art.md), appendix), instead of today's why / picture / blast radius
/ Door / verification body.

## Behaviour

The **Push and PR** bullet on the body in `plugins/flows/steps/close.toml` becomes T3's rules, written by the session
that did the work (no separate model call):

- **Title:** concise and specific.
- **Body without a template:** markdown with the headings `## Summary` and `## Testing`. Summary: short bullet points.
  Testing: one bullet per command of Decide's **Checks** row and its result, and `Not run: <check>` for each
  **Skipped** row.
- **Body with a template:** when the repository has a pull request template (`pull_request_template.md`, or a
  `PULL_REQUEST_TEMPLATE/` folder of them, in its root, `docs/` or `.github/`, any case), the body follows its markdown
  structure, fills its sections for this change and drops its HTML comments. With several, the session picks the one
  that fits and names it at the PR gate.
- **Never** in the body: absolute local paths, image embeds or attachment links; reviewers can't open them.
- The body is still saved to a scratchpad file.

Unchanged: the PR gate (title, body and closing commit approved with one yes), the user running `git push -u` and
`gh pr create --title --body-file`, watching checks, the closing commit, merge-conflict handling.

## Out of scope

- T3's commit-message prompt (the repo's commit rule stays: one sentence).
- Pushing or creating the PR for the user, linking or watching it the T3 way.
- A one-shot model call over a capped diff (T3's truncation, JSON output, thread fencing): the in-session agent
  already has the diff and the run's history.
- Attribution lines: T3 adds them only when a template asks; the host's own attribution rules stay as they are.

## Seams

- PR text format: resolved in `plugins/flows/steps/close.toml`; never seen by the conductors' SKILL.md files, the
  host templates or the packs.

## Affected

- `plugins/flows/steps/close.toml`: the body bullet; `pstack-picks:blast-radius` leaves its `uses` (nothing else in
  the step uses it). The conductors that list blast-radius for their own phases keep it.
- Built output for the six conductors that compose `[step: close]` (build-feature, fix, implement, refactor, upgrade,
  review-code), regenerated by `npm run build:harnesses`.

## Done when

- The composed Close step in every conductor carries T3's title and body rules and no longer asks for a picture,
  blast radius or Door line.
- `npm test` passes (check-repo, the compiler's lint and the overrides markers included).
