## Part (a): looking like one person

### Approach A1: humanise in the driver, keep a real browser
- Shape: stock browser, input events sent with person-like timing and paths. Camoufox runs the `myuri` engine in the caller's process (`humanize=True`); agent-browser has `mouse move --human --seed`, `--duration`, `--steps` and `type --delay`.
- Who: Camoufox [README, "Human input"](https://github.com/daijro/camoufox) says the browser adds no timing, paths or randomness, the driver does, and settings (typing wpm, speed, mistakes) take a seed. agent-browser [commands](https://agent-browser.dev/commands) lists `--human`, `--seed`, `type --delay 10`. Playwright MCP only has `browser_type slowly` ("one character at a time", for key handlers) and a `delay` on `mouse_click_xy` ([README](https://github.com/microsoft/playwright-mcp)).
- Good at: cheap, no fingerprint changes (fits ADR 0004/0009). Fixes the "one key press each, no delay" tell.
- Costs: latency per query; each event is a round trip over a CLI, so timing jitter from the CLI may dominate [inferred]. Camoufox warns of round trips over a network for humanize.
- Bad fit if: blocks come from IP reputation or fingerprint, not behaviour [inferred]. rebrowser says its patches do not cover "script behavior such as timing and mouse movement" nor IP reputation ([README](https://github.com/rebrowser/rebrowser-patches)), which shows behaviour is a separate layer [source].

### Approach A2: one identity across HTTP and browser
- Shape: pin UA, headers, cookies, TLS/HTTP2 fingerprint so both paths look like the same client.
- Who: curl-impersonate copies a real browser's TLS and HTTP/2 handshake ([README](https://github.com/lexiforest/curl-impersonate)); impit is a Rust wrapper over reqwest with patched rustls/h2 and a fingerprint DB, "Without the patched dependencies, the project won't build" ([README](https://github.com/apify/impit)). Camoufox makes headers match navigator "always" ([README, comparison](https://github.com/daijro/camoufox)). Crawlee ties cookies, proxy and headers to a session ([session docs](https://crawlee.dev/js/docs/guides/session-management)).
- Good at: removes UA/TLS mismatch between `fetch` and `browser`.
- Costs: impit needs git-patched crates (a supply-chain and build burden; fits badly with a root `Cargo.lock` policy [inferred]); impersonation profiles age (curl-impersonate lists Chrome 99-152 and warns some flags alter the TLS signature [source]). Sending a Chrome UA with reqwest's own TLS likely creates a mismatch worse than an honest UA [inferred, nothing cited here; literature E6/E7 point that way].
- Bad fit if: the policy is "no faked UA" (it is). The cheaper variant inside policy: send the browser's real UA and `Accept-Language` on `fetch`, and share cookies only deliberately [inferred].

### Approach A3: pacing, sessions, retirement
- Shape: spread requests, retire a session when blocked, treat network errors differently from blocks. Crawlee `retireOnBlockedStatusCodes`, `markBad()` for socket errors ([docs](https://crawlee.dev/js/docs/guides/session-management)).
- Good at: parallel Google/Bing/DDG/Brave on one IP is a burst; whether per-engine delay and backoff would lower web-mcp's block rate is unmeasured (source check: not supported; literature E10). Crawlee page gave no numbers for rate limits or backoff [source gap].
- Bad fit: a single user's occasional search needs no session pool [inferred].

### Approach A4: full stealth stack
- Patchright (Chromium only; avoids `Runtime.enable`, disables Console API, changes launch flags, lists passes of Cloudflare, Kasada, DataDome) [README](https://github.com/Kaliiiiiiiiii-Vinyzu/patchright). Its own [issue 30](https://github.com/Kaliiiiiiiiii-Vinyzu/patchright/issues/30) says console events cannot work and WebSocket routing is likely unsolvable without a MITM proxy.
- rebrowser-patches: `Runtime.enable` fix with modes, tested only on specific Puppeteer/Playwright versions, "npm install can overwrite them", does not cover HeadlessChrome UA, canvas/WebGL or IP [README](https://github.com/rebrowser/rebrowser-patches).
- nodriver: no WebDriver, direct CDP, "official successor" of undetected-chromedriver; `expert=True` "makes you more detectable"; no humanisation mentioned [README](https://github.com/ultrafunkamsterdam/nodriver).
- puppeteer-extra-stealth: README gives no deprecation notice, newest changelog v2.4.7, says headless detection is "probably impossible to prevent" fully [README](https://github.com/berstend/puppeteer-extra/tree/master/packages/puppeteer-extra-plugin-stealth). Whether it still works: not shown by the page [gap].
- Camoufox: patched Firefox, spoofing in C++, coherence-checked identity; own README: "Camoufox can still be detected", "under development", Firefox identities only [README](https://github.com/daijro/camoufox). Crawl4AI offers `enable_stealth` via playwright-stealth, default False [docs](https://docs.crawl4ai.com/core/browser-crawler-config/).
- Good at: sites with active bot vendors. Costs: patches break on driver upgrades (rebrowser, Patchright "fixes might take a few days"); Patchright/rebrowser patch Playwright/Puppeteer, and web-mcp drives Chrome through the agent-browser CLI, so neither applies without swapping the driver [inferred]. Vendor "passes" are self-reported [source: READMEs]. Bad fit: ADR 0004/0009 policy; a headed real Chrome with a persistent profile already avoids several tells [inferred].
- If an opt-in is wanted: Camoufox is the only one that is a browser, not a driver patch, but it is Firefox/Python/Playwright, a second engine [inferred].

### agent-browser constraints
Per [commands](https://agent-browser.dev/commands): `--user-agent`/`AGENT_BROWSER_USER_AGENT`, `--headers <json>` "scoped to URL's origin", `set headers`, `--args`, `type --delay`, `mouse move --human`. The page doesn't say what `--delay` unit or default is, or how `--human` paths look [gap]; check `--help` on 0.41.x before relying.

## Part (b): injection in what tools return

### Approach B1: mark the content (delimit, datamark, encode)
- Spotlighting: random delimiters, a mark between words, or base64/ROT13, plus a system-prompt line ([MSRC](https://www.microsoft.com/en-us/msrc/blog/2025/07/how-microsoft-defends-against-indirect-prompt-injection-attacks)); abstract reports attack success from over 50% to under 2% on GPT-family models ([arXiv](https://arxiv.org/abs/2403.14720)). agent-browser `--content-boundaries` wraps `snapshot`, `get text`, `get html`, `eval`, `console` in `--- AGENT_BROWSER_PAGE_CONTENT nonce=... origin=... ---`, per-process nonce, and says it is defence-in-depth that depends on the orchestrator ([security](https://agent-browser.dev/security)). The fetch MCP server adds only `Contents of <url>:` and no marking ([server.py](https://raw.githubusercontent.com/modelcontextprotocol/servers/main/src/fetch/src/mcp_server_fetch/server.py)).
- Good at: cheap, no false positives. Costs: relies on the model; datamarking/encoding change the text (summarising quality) [inferred, MSRC says each mode has trade-offs]. Bad fit: a static "do not follow" line (today's) has a fixed string the page can imitate; a nonce does not [inferred]. Does web-mcp already get agent-browser's markers? Turning on `--content-boundaries` is a flag, to verify [inferred].

### Approach B2: sanitise what the page sends
- Hidden text: Unicode Tags carry invisible instructions (the U+E0000 range is ours, not the blog's); recommended mitigation is "filtering out the Unicode Tags Code Points at prompting and response times" ([Rehberger, blog](https://embracethered.com/blog/posts/2024/hiding-and-finding-text-with-unicode-tags/)). Readability-based tools drop `hidden`, `aria-hidden`, `display:none`; the fetch server's code reuses Readability.js's rule and even un-hides large hidden blocks when they hold the real page (`_recover_hidden_content`), so extraction is not a security filter [source, code]. Jina Reader has `x-detach-invisibles` for `display:none` ([README](https://github.com/jina-ai/reader)).
- Good at: deterministic, testable. Costs: arbitrary stripping of zero-width joiners breaks emoji, Indic and Arabic text [inferred]; strip only the Tags block and bidi controls, flag the rest [inferred]. Comment and CSS-hidden stripping is partial: off-screen, tiny and same-colour text survive [inferred].
- Bad fit as only defence: instructions can be plain visible text [MSRC: even an ASCII `.txt` works].

### Approach B3: restrict what the model can do after reading
- Playwright MCP: `--allowed-origins`/`--blocked-origins` ("does not serve as a security boundary and does not affect redirects"), file access limited to workspace, `browser_run_code_unsafe` named "RCE-equivalent", `browser_evaluate` read-only false, README: "not a security boundary" ([README](https://github.com/microsoft/playwright-mcp)). agent-browser: `--allowed-domains` (blocks sub-resources, best-effort for WebSocket, "For maximum protection, deny the eval category via --action-policy"), `--action-policy` with `eval`/`navigate` categories, `--confirm-actions` ([security](https://agent-browser.dev/security)). Browser Use: `allowed_domains`, `prohibited_domains`, `block_ip_addresses` ([parameters](https://docs.browser-use.com/customize/browser/all-parameters)). Fetch server: refuses private addresses on every hop, pins the connection to the checked address, caps body at 5 MiB, `--allow-private-ips` opt-in, optional `--allowed-hosts`, `ToolAnnotations(read_only_hint=True, open_world_hint=True)` ([server.py](https://raw.githubusercontent.com/modelcontextprotocol/servers/main/src/fetch/src/mcp_server_fetch/server.py)). MSRC: deterministic blocks on exfil channels (markdown images, links) and human confirmation ([MSRC](https://www.microsoft.com/en-us/msrc/blog/2025/07/how-microsoft-defends-against-indirect-prompt-injection-attacks)). OpenAI: confirmations for consequential actions, logged-out mode ([post](https://openai.com/index/hardening-atlas-against-prompt-injection/)).
- Good at: the only class with hard guarantees [MSRC]. Costs: friction for the user's localhost workflow; allowlists need CDN hosts [inferred; agent-browser blocks sub-resources to non-allowed domains]. Bad fit: URL-param exfiltration through a `fetch` to an attacker URL is not stopped by blocking private IPs; needs an allowlist or confirmation on URLs the model built from page text [inferred].
- Design hint for web-mcp: the fetch server's private-address guard is opt-out, web-mcp's is opt-in off; a per-call or per-session "localhost allowed" switch fits the user's use [inferred].

### Approach B4: classifiers and model training
- Anthropic: RL training plus classifiers on all untrusted content; Opus 4.5 attack success 1.4% with safeguards, "A 1% attack success rate ... still represents meaningful risk" ([post](https://www.anthropic.com/research/prompt-injection-defenses)). Prompt Shields: probabilistic classifier API ([MSRC](https://www.microsoft.com/en-us/msrc/blog/2025/07/how-microsoft-defends-against-indirect-prompt-injection-attacks)). LlamaFirewall: PromptGuard 2 (BERT-style, scans untrusted web data), AlignmentCheck (reasoning audit); models download from HuggingFace, page states no limits ([README](https://github.com/meta-llama/PurpleLlama/tree/main/LlamaFirewall)). OpenAI: injection is "an open challenge".
- Good at: catches natural-language attacks. Costs: a model download and latency per page, false positives on pages about security [inferred]; the Anthropic/OpenAI ones are not usable from your server. Bad fit: a stdio Rust server with no Python runtime [inferred].

## Protocol constraints (MCP 2025-11-25, [tools spec](https://modelcontextprotocol.io/specification/2025-11-25/server/tools))
- Annotations are optional and "clients MUST consider tool annotations to be untrusted unless they come from trusted servers": hints help UI, enforce nothing.
- Servers MUST "Sanitize tool outputs" and "Rate limit tool invocations"; clients SHOULD validate results before the model sees them. That is the spec wording for your two concerns.
- `isError: true` is the channel for failures the model can retry (e.g. block or captcha); text content can carry annotations (`audience`, `priority`).

## Pitfalls
- Stealth is a moving target: Camoufox and puppeteer-extra say they can still be detected and rebrowser lists what it doesn't cover; Patchright claims to be "currently … considered undetectable" (self-reported), nodriver makes no claim (source check: corrected).
- Allowlists leak: Playwright's origin filter ignores redirects; agent-browser's WebSocket blocking is best-effort.
- Extractors are not sanitisers: Readability keeps or revives hidden text depending on size (fetch server code).
- Delimiters help only if the model is told about them; MSRC pairs them with a system-prompt change [source]. A tool cannot change the host's system prompt, so a nonce plus a one-line rule in the reply is the closest [inferred].
- Not found: a published postmortem on humanisation slowing a scraper, or an MCP server that strips Unicode tags (search failed).
