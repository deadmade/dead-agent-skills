# VS Code extension test run reports REST Client as not installed

- **Seen:** 2026-11-09, checking that an agent-written `.http` file runs in the real REST Client extension on a machine without VS Code. `vscode.extensions.getExtension("humao.rest-client")` returned nothing, though `--install-extension` had succeeded into the same `--extensions-dir`.
- **Cause:** a run started with `--extensionTestsPath` loaded only built-in and development extensions in VSCodium 1.116.0; the extension installed in `--extensions-dir` did not load (measured with `vscode.extensions.all`).
- **Fix:** pass the installed extension's folder as a second `--extensionDevelopmentPath` beside the harness. Run `nix shell nixpkgs#vscodium nixpkgs#xvfb-run --command xvfb-run -a codium --wait --user-data-dir <d> --extensions-dir <e> --extensionDevelopmentPath=<harness> --extensionDevelopmentPath=<e>/humao.rest-client-0.25.0-universal --extensionTestsPath=<harness>/tests.js <folder>`. The harness puts the cursor on the request and calls `rest-client.request`. Setting `rest-client.previewResponseInUntitledDocument` to true makes the reply readable from `vscode.workspace.textDocuments`, since the default webview cannot be read. Set `HOME` to a throwaway folder, because REST Client writes its history there.
- **Spot it next time:** report `vscode.extensions.all` when an extension seems missing, before suspecting the install.
